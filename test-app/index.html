🔍 How to Verify the Protection Works

1
Convert & Encrypt a File
Go to the Encrypt tab, enable "Encrypt output file", convert any .ply file, and download the result. Notice the file extension is .esog instead of .sog.
2
Try Opening the Encrypted File
Try to open the .esog file in a hex editor or any splat viewer. You'll see it starts with ESPL (our magic bytes) followed by random-looking data. It's completely unusable without the key.
3
Decrypt with Correct Key
Go to the Decrypt tab, upload the .esog file, paste the key you saved, and click Decrypt. The file will be restored perfectly.
4
Try Wrong Key
Try decrypting with a wrong key or modified key. You'll get an error: Decryption failed: invalid key or corrupted data. AES-GCM detects tampering!
5
Open DevTools Network Tab
Press F12 → Network tab. Convert a file with encryption enabled. You'll see no key is transmitted anywhere - it's generated client-side. In a real SaaS, the key would come from your backend API.
6
Test Obfuscated Mode
Go to the Obfuscated tab and encrypt a file. Notice how the key is split into 4 fragments. In production, each fragment would come from a different API endpoint, making it much harder for attackers to intercept the complete key.
